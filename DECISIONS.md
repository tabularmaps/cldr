# Decision log

Append-only. Entries are numbered and never rewritten; a later entry may
supersede an earlier one and says so. Each entry separates **fact**,
**hypothesis**, and **normative choice** where the distinction matters.
Present-tense truth lives in `README.md`; this file is the past-tense record.

## D1 — The mother set is "CLDR `regular` two-letter region identifiers" (2026-09-17)

**Fact.** Unicode CLDR `common/validity/region.xml` classifies region
identifiers by `idStatus`: regular, special, macroregion, deprecated,
reserved, private_use, unknown. In release 48.2 the `regular` class holds
257 identifiers, all two-letter.

**Normative choice.** The project's primary profile is the `regular` class,
restricted to `^[A-Z]{2}$`, taken from one pinned release. Reasons:

- `regular` is exactly CLDR's notion of "a current geographic territory you
  can localize for"; macroregions, groupings (EU, UN), special codes (XA/XB
  pseudo-locales), private-use and deprecated codes are not places.
- The rule is mechanical and testable; it delegates every inclusion decision
  to an externally governed, versioned process (CLDR's Technical Committee)
  rather than to this project.
- ISO 3166-1 alone would omit AC, CP, CQ, DG, EA, IC, TA and XK, which CLDR
  treats as first-class territories and which real localization data uses.

**Non-choice.** Inclusion says nothing about statehood, recognition or
sovereignty (see README non-claims).

## D2 — CLDR 48.2 is pinned by archive checksum, not by branch (2026-09-17)

**Fact.** `cldr-common-48.2.zip` (sha512 `de8660f5…`, listed in unicode.org's
`hashes/SHASUM512.txt`) and git tag `release-48-2` (commit `11299982…`)
contain byte-identical `common/validity/region.xml` (sha256 `e751e0ee…`).
The tag's `LICENSE` differs from the archive's only in the copyright years
and a BOM; the archive copy is the one committed.

**Normative choice.** The archive is the normative input; the git tag is the
convenience mirror. `data/profile.json` records version, tag, commit,
archive URL, both checksums, extraction rule and date. Tests fail with an
"explicit maintenance event" message if the committed `region.xml` changes
without the profile changing.

## D3 — 256 cells are not preserved (2026-09-17)

**Fact.** The predecessor `tabularmaps/8bit` holds 250 identifiers (249 ISO
3166-1 alpha-2 + XK) in 16×16 = 256 cells. CLDR 48.2 `regular` has 257.

**Normative choice.** The board adapts to the mother set; the mother set is
not trimmed to the board. 256 was a temporary numerical fit (the CQ addition
in CLDR 42 already broke it), not a semantic boundary. Any single removal
would be a project-specific judgement about which territory is dispensable
and would contradict "one identifier, one equal cell". The full reasoning
is in `CLAUDE.md` § "Why the project does not preserve 256 cells".

## D4 — No identifier is dropped, none is added (2026-09-17)

**Fact.** `data/regions.json` is generated by `scripts/extract_cldr_regions.py`
from the pinned file and contains exactly the 257 extracted identifiers;
`tests/test_mother_set.py` asserts this and the 249 + 8 relationship to ISO
3166-1 (the latter as a report, using the 8bit board and `pycountry`
26.2.16 as references, not as authorities).

**Normative choice.** Hand-editing `data/regions.json` is forbidden; the
board validator rejects any board that omits or adds an identifier.

## D5 — Geographic sources: Wikidata points, Natural Earth adjacency, CLDR containment (2026-09-17)

**Options considered.**

- *Natural Earth polygons for points*: public domain, but the admin-0
  layers do not carry AC, CP, CQ, DG, EA, IC, TA (and UM only as scattered
  US units), and the largest-polygon centroid is misleading for scattered
  states (Kiribati → Kiritimati, Malaysia → Borneo).
- *mledoze/countries* (`latlng`, `borders`): convenient, but ODbL
  share-alike sits awkwardly in a CC0 repository, and it is ISO-scoped.
- *Wikidata P297 + P625*: CC0, covers all 255 ISO+XK+AC+CP+CQ+DG+TA+UM
  codes through a single reproducible SPARQL query, and the item's own
  coordinate is a reasonable "where people think this place is" point.
- *Natural Earth 10m map units for adjacency*: public domain and
  topologically consistent, so land borders can be derived mechanically
  from shared vertices without a geometry library.
- *Wikidata P47 (shares border with)*: CC0 but mixes maritime and land
  borders inconsistently.

**Normative choice.** Wikidata for points (rule: lowest Q-number item with
P297 = id), Natural Earth 5.1.2 map units for land adjacency (rule: ≥ 2
shared vertices), CLDR's own `territoryContainment` for the regional
classification so no additional source is needed. Two points (EA, IC) and
two adjacency pairs (CN–MO, EA–MA) are reviewed manual supplements with
notes. Details in `SOURCES.md`.

## D6 — Disputed and ambiguous geometry is bounded by source policy, not project judgement (2026-09-17)

**Fact.** Natural Earth includes units with no ISO code (Somaliland,
Northern Cyprus, Korean DMZ halves, UNDOF zone, Siachen, Bir Tawil, …).

**Normative choice.** A unit maps to an identifier by Natural Earth's own
fields, in order `ISO_A2_EH` → `ADM0_ISO` (Natural Earth's "ISO point of
view") → `ADM0_A3`; anything still unmapped is dropped and listed in
`data/geo/ne_units.json`. Consequences: Somaliland's borders count for SO,
Northern Cyprus for CY, the DMZ yields KP–KR, UNDOF yields IL–SY. Pairs that
share only one vertex (BW–ZM, NA–ZW at the Kazungula quadripoint) are
rejected by the mechanical rule and not restored by hand. The project makes
no border judgement of its own; changing a mapping requires a new decision
entry.

## D7 — Longitude order is Atlantic-centred with a cut at 125° W (2026-09-17)

**Fact.** Distances use the haversine formula and are unaffected by the
antimeridian. East–west *order* needs a cut. Representative points west of
125° W are exactly the Polynesian territories (AS, CK, NU, PF, PN, TK, TO,
WF, WS); every point of the Americas lies east of it.

**Normative choice.** Longitudes ≤ −125° are unwrapped by +360°, so the
Pacific islands sort east of New Zealand and Fiji, as on the `8bit` board.
Tested in `tests/test_geo.py`.

## D8 — Objective function: seven scored components plus a reported legacy term (2026-09-17)

**Normative choice.** See `OPTIMIZATION.md` for definitions and weights. The
design principles were: every component must be computable for an
arbitrary board without the optimizer; pairwise components are expressed
as Σ F[i,j]·D[cell_i, cell_j] so annealing can evaluate a move in O(n); no
component may use the answer (no hand-drawn target positions); the
whitespace term penalises only enclosed holes, leaving where the blanks go
to the other components.

**Superseded parameters (same day).** A first calibration used direction
thresholds of 20° longitude / 15° latitude with weight 1.0 and a
false-adjacency distance of 3000 km with no neighbourhood exclusion. Human
review of the first 19×14 result showed intra-European order scrambled and
Ceuta placed beside Kosovo without penalty, so the thresholds were lowered
to 12° / 8° (weight 2.0) and false adjacency redefined as "> 2000 km and
not within each other's 12 nearest neighbours" so that legitimate island
neighbours (AU–NZ, PF–PN) are not penalised. This is recorded as a change
of the objective, not as a manual edit of a board.

## D9 — Simulated annealing with single-item relocation moves (2026-09-17)

**Options considered.** Exact QAP methods are out of reach at n = 257 with a
non-separable objective. Genetic search and tabu search were not tried.
Two-stage "human territory map + intra-territory optimization" (the method
the sibling project `tabularmaps/do` settled on) is supported through the
optional `--territories` constraint but is not the primary method: the
grid-comparison must treat every grid identically, and a hand-drawn map per
grid would confound the comparison.

**Normative choice.** Geometric cooling from t0 = 0.02 to 1e-4; moves relocate
one identifier to a random cell within Chebyshev radius 2 (probability
0.7), to a cell adjacent to one of its six geographic neighbours (0.2), or
anywhere (0.1); a starting layout from quantile-scaled longitude/latitude
assigned by linear sum assignment; several seeds; the best chain is kept
and re-scored from scratch. Calibration (t0 from 0.005 to 0.05 at 300 k
iterations, budgets from 300 k to 5 M) is summarised in `OPTIMIZATION.md`
§ 2 and § 4; a first attempt with t0 = 0.25 (twice the median move cost)
never recovered the quality of its starting layout and was abandoned.

## D10 — The default grid is 20 × 14, not the hypothesised 19 × 14 (2026-09-17)

**Fact.** Under identical objective, start, seeds (1–4) and budget (3 M
iterations per seed), the best/mean combined scores were: 17 × 16
3.695/3.717, 18 × 15 3.614/3.700, 19 × 14 3.676/3.699, 20 × 13 3.730/3.749,
**20 × 14 3.549/3.571**, 22 × 12 3.729/3.764, 24 × 12 3.596/3.641
(`reports/grid-comparison.md`). 20 × 14 was better than every other grid's
best result on each of its four seeds.

**Hypothesis tested.** The project brief proposed 19 × 14 (9 blanks). It was
not confirmed: it ties 17 × 16 and 18 × 15 within seed noise and loses to
20 × 14 by about twice the seed spread.

**Normative choice.** 20 × 14 (280 cells, 23 structural blanks, aspect 1.43)
is the default grid. Cartographic review of the best boards supported the
numbers: the 20 × 14 blanks read as the Arctic margin, an Indian Ocean
block, a South Atlantic island column and Pacific corners rather than as
holes; Oceania keeps a Micronesia–Melanesia–Polynesia north–south order;
Africa, South America and East Asia are compact. The known weakness shared
by all compact grids is the absence of an Atlantic gap: the Channel Islands
touch the Caribbean column. 24 × 12 opens that gap but scores worse, has a
2:1 aspect and fragments its whitespace. Compactness was weighed against
whitespace by the score itself (which is not monotonic in blank count) and
by review, not by a separate compactness term.

## D11 — Selected layout: 20 × 14, seed 1 of 8 at 5 M iterations, no pins (2026-09-17)

**Fact.** Eight chains of 5 M iterations on 20 × 14 gave combined scores
3.509, 3.580, 3.549, 3.546, 3.542, 3.512, 3.540, 3.544 (seeds 1–8). Seed 1
was kept; its recorded score is re-verified by `scripts/validate_board.py`.

**Review.** The seed-1 board was the only 20 × 14 board with both a North
Atlantic gap (between GL/VI/AI and IS/IM/GG) and a South Atlantic island
column, in addition to the Indian Ocean block shared by all 20 × 14 boards
(`OPTIMIZATION.md` § 6). Weaknesses noted and accepted: NO placed between
DK and LT, BH isolated beside DJ, HM/CC on the bottom row near NZ, a dense
Europe without a Mediterranean gap.

**Normative choice.** No manual pins. The committed board is exactly the
optimizer's output, so it can be regenerated with the recorded command,
seed and budget. Pins remain available (`--pins`) for future maintainers;
each requires a decision entry with before/after scores.

## D12 — What "optimal" means here (2026-09-17)

The board is *the best layout found under the documented objective,
weights, inputs, seeds and search budget*. It is not a proven global
optimum: the objective is a normative construction (D8), the search is
heuristic (D9), and seeds differ by up to ~0.07 on the selected grid. The
README, OPTIMIZATION.md and metadata avoid the unqualified word "optimal".
A better board under the same objective is welcome as a pull request that
includes its `scripts/score_layout.py` report.

## D13 — Future CLDR releases are explicit maintenance events (2026-09-17)

**Normative choice.** The committed board never changes because CLDR
changed; it changes because a maintainer ran the documented procedure
(README § "Updating to a newer CLDR release"): pin the new archive with
checksums, regenerate and diff `data/regions.json`, classify additions,
removals and deprecations, extend the geographic inputs with sourced
supplements, decide between stable insertion into existing whitespace
(there are 23 blanks, distributed as seas) and re-optimization, regenerate
artifacts and reports, and add a decision entry. Tests enforce the first
step: a changed `region.xml` without a matching profile fails with an
"explicit maintenance event" message. Removed or deprecated identifiers are
never silently kept; the profile name carries the CLDR version so that
consumers can detect the change.

## D14 — An optional "UN members" preview is an experimental view, not part of the data (2026-09-17)

**Fact.** CLDR's `territoryContainment` includes a `UN` grouping of 193
identifiers. `data/regions.json` reproduces it as `un_member`, and
`scripts/render_preview.py --only-un-members` draws the other 64
identifiers as faint outlines in their normal cells.

**Boundary.** The default preview, `board.csv`, `metadata.json` and the
layout contain no such distinction; the layout is not influenced by it.
The filter exists because a dashboard may need to show a UN-scoped
indicator, and the honest way to do that on an equal-cell map is to keep
every cell in place and mute the ones outside the indicator's scope. The
set is CLDR's, not this project's: showing PS, VA, TW, XK, HK, MO, EH, or
any territory as "outside the UN grouping" restates CLDR data and expresses
no view on status. The view is not linked from the README and is not
published in `docs/`.
